# QA Lab｜軟體測試作品集

目前作品集版本為 **v1.0.0**。

QA Lab 包含兩個獨立練習專案。入口是 `dist/index.html#projects`。

| 專案 | 瀏覽器入口 | 展示能力 |
| --- | --- | --- |
| 電商結帳品質驗證 | `dist/index.html` | 介面操作、商業規則、缺陷重現及交易回歸 |
| 預約系統 API 測試 | `dist/booking.html` | HTTP 合約、並行請求、狀態轉移、錯誤驗證 |

工作區中的 `QA-Lab.html` 和 `QA-Lab-Booking.html` 可單獨開啟。兩個檔案放在同一個資料夾時可互相切換。

## 電商結帳品質驗證

互動實驗室支援購物車、優惠碼、三種配送方式、付款結果、重複送單、訂單取消和庫存回補。

## 面試演示

若要分享網站資料夾，請保留 `dist` 的全部檔案。

1. 在缺陷回報依模組篩選，選擇「載入缺陷情境」。
2. 切換至修正後。實驗室會以相同輸入重新計算，並重跑原本的下單與取消操作。
3. 在「回歸測試案例」開啟對應案例，比對輸入、操作和逐項結果。也可以下載所選版本的完整 JSON 報告。
4. 手動演示時，可先設定付款遭拒並送出，再改為付款成功連續送出兩次，驗證只成立一筆訂單。取消後可核對庫存回到起始數量。

## 商業規則與測試範圍

- 每款商品數量可為 0 到 5 的整數，且不能超過可售庫存。單筆購物車最多 8 件。
- 商品小計滿 NT$500 可用 DEMO100 折 NT$100。英文字母不分大小寫，已過期的 EXPIRED100 不能折抵。
- 本島宅配 NT$80，折後滿 NT$700 免運。超商固定 NT$60，離島固定 NT$140。
- 下單前須有收件人、以 09 開頭的十碼手機號碼及付款成功結果。每次結帳僅成立一筆訂單，取消時回補庫存。購物車、配送或收件資料變更會開始一個新的模擬結帳。
- 付款與訂單操作在瀏覽器本機模擬。真實支付、物流 API、帳戶與持久化庫存屬於展示範圍之外。

## 執行自動化測試

使用 Node.js 18 以上版本，無須安裝套件。瀏覽器和 CLI 共用 29 個回歸案例。修正後的 CLI 另驗證單品數量上限和格式、付款重試以及重複取消，預期 33／33 通過。

```powershell
node --test tests/checkout.test.cjs
```

修正前預期 13 個缺陷對應的案例失敗。瀏覽器結果為 16／29 通過，可用 CLI 驗證同一組缺陷。

```powershell
$env:QA_VERSION = 'legacy'
node --test tests/checkout.test.cjs
Remove-Item Env:QA_VERSION
```

`dist/checkout.js` 包含雙版本邏輯與回歸案例，`dist/app.js` 負責互動與報告匯出，`tests/checkout.test.cjs` 是 Node 測試入口。

## 預約系統 API 測試

以三個固定時段和測試訪客為資料。網站在瀏覽器執行模擬 API，每個案例使用獨立資料。可手動編輯方法、路徑、JSON 本文，或載入缺陷後用同一組請求比較版本。請求紀錄可檢查每次的狀態碼、回應標頭和 JSON。

| 方法和路徑 | 成功回應 | 驗證重點 |
| --- | --- | --- |
| `GET /api/slots` | 200 | 時段資料及可用狀態 |
| `POST /api/bookings` | 201 | 必填欄位、衝突回傳 409、Location 標頭 |
| `GET /api/bookings/BK-001` | 200 | 建立或取消後的預約狀態 |
| `DELETE /api/bookings/BK-001` | 204 | 無本文、取消後時段釋出、重複取消 |

修正前有三個缺陷，分別是重複預約、取消後時段仍顯示占用、接受空白姓名。12 個網頁案例中，修正前 8 個通過，修正後 12 個通過。

Node.js 18 以上版本可使用下列指令。兩個專案的修正後測試合計 46 項。

```powershell
npm test
npm run test:booking
```

`npm run booking:api` 在本機的 `127.0.0.1:8780` 啟動同一組模擬邏輯，可從另一個終端用 `curl.exe http://127.0.0.1:8780/api/slots` 檢查 HTTP 回應。整合測試會實際透過本機 HTTP 同時送出兩筆預約，再取消並重訂。服務重新啟動時會重設示範資料。

將 `BOOKING_VERSION` 設成 `legacy` 可驗證修正前結果。修正前的 4 個網頁案例與 1 個 HTTP 整合案例會按預期失敗。
